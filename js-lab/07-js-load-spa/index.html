Dynamic Project Loader — SPA Upgrade

After learning and completing the page loader described above, I started upgrading my website into a Single Page Application (SPA). I began adding my projects and games directly into their respective HTML pages. But after adding several projects, I started thinking: “Wait, could I load projects dynamically, just like I load a page?”

That question led me to build this dynamic project loader, making my SPA more flexible and easier to maintain. Instead of manually writing every project card in HTML, I moved the project information into JavaScript data arrays and created reusable functions to generate and display project cards dynamically.

Storing Data

First, I stored the project information in arrays of objects, including titles, descriptions, categories, programming languages, preview images, project links, dates, and view counts. These are the properties I use to build my project cards.

Then, I used JavaScript array methods to organize the data into different sections. For the Latest Projects section, I used sort() to arrange projects by date, from newest to oldest, and slice() to control how many cards to display.

For the Popular Projects section, I used the view counts stored in the data. I sorted the projects by their views and used slice() to display the most popular ones. For now, these view counts are manually defined in the data. In the future, I plan to upgrade this feature to use a database when I'm ready to work with one. That's one of the exciting possibilities of this system.

For the Featured Projects section, the logic is simple: I added a feature property to each project. If its value is true, that project appears in the featured section.

For the All Projects section, I rendered the entire project collection. I also created separate data arrays for upcoming projects and games. Keeping these collections organized makes the system easier to maintain and gives me a clear place to add new projects in the future.

Testing error handling: I also created "Art" page that doesn't actually exist to test what happens when a page fails to load. When I try to load that page, the website displays the message, “The page could not be loaded.” This helped me check whether my error-handling logic works as expected.

Rendering and Loading Data On Pages

After storing the data, I created reusable functions to generate and render project cards.

The projectCard(project) function builds an individual card from a project object, while renderProject(projects, place) takes a collection of projects and renders them into their designated HTML container.

I then created separate functions for rendering the content on the Home, Projects, and Games pages. Each function handles the sections belonging to its page, such as featured, latest, popular, all, and upcoming projects or games.

Finally, I connected these functions through a single loadProjects(page) function. After loadPage() fetches and inserts the requested HTML page, it calls loadProjects(page) to render the appropriate content.

This means the HTML provides the containers, while JavaScript supplies the data and builds the project cards dynamically.

Conclusion

This upgrade helped me understand how to separate data, rendering logic, and page structure. I also learned that a single collection of project data can power multiple sections, such as Featured Projects, Latest Projects, Popular Projects, and All Projects, without rebuilding the same cards for each section. What I especially love about this system is that whenever I finish a new project, I only need to add its information to the data array instead of writing multiple lines of HTML for every card. The system then uses that data to generate the cards wherever they're needed. Most importantly, I learned to turn a question that came from my own coding experience into a practical solution.
